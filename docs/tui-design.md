# Agents Farm — термінальний застосунок (TUI): варіанти та ескізи

Мета: на одному екрані бачити **хто з агентів що робить**, **контекст задачі** (з можливістю розгорнути) і **скільки лишилось лімітів по моделях** — щоб вчасно помітити, що агент застряг, чекає на тебе, або модель от-от упреться в ліміт.

---

## 0. Спільні елементи (для всіх варіантів)

### Статуси агента — колір + символ (ніколи лише колір)

| Символ | Статус | Колір | Значення |
|---|---|---|---|
| `●` | running | зелений | працює, є свіжий вивід |
| `◐` | thinking | блакитний (анімований спінер `⠋⠙⠹⠸`) | чекає відповіді моделі |
| `?` | waiting | **жовтий, жирний** | чекає на тебе (дозвіл / питання) — найважливіше |
| `!` | error | червоний | впав / ретраї вичерпано |
| `◌` | idle | сірий | немає задачі |
| `✓` | done | приглушено-зелений | завершив, треба переглянути |
| `⏸` | stalled | помаранчевий | >N хв без активності |

### Лімітний бар по моделі

```
opus-5.5    ████████████░░░░░░░░  62%  ↻ 1h12m   tok 1.2M/2M   $4.10
sonnet-5.5  ███████████████████░  94%  ↻ 0h08m   ⚠ скоро ліміт
haiku-5.5   ███░░░░░░░░░░░░░░░░░  14%  ↻ 3h40m
```

Пороги: `<70%` зелений · `70–90%` жовтий · `>90%` червоний + `⚠` + рядок піднімається в status bar.
Показуємо **час до скидання** (`↻`), а не лише відсоток — бо дія користувача залежить саме від нього.
Опційно — прогноз: «при поточній швидкості закінчиться за ~25 хв».

### Підсвітка задач

- Задача з `waiting` — завжди вгорі списку, жовтий фон рядка.
- Фільтр-пошук `/` підсвічує збіги жирним.
- Свіжі зміни (останні 5 с) — короткий «спалах» інверсією, потім згасає.

## Варіант B — «Kanban» (колонки за статусом)

Добре, коли агенти — це конвеєр задач і важливий потік: що в черзі, що в роботі, що чекає рев'ю.

```
┌ agents-farm ── board ─────────────────────────────────────────────────────────┐
│ QUEUE (3)          │ RUNNING (3)         │ NEEDS YOU (2)      │ DONE (5)       │
│────────────────────│─────────────────────│────────────────────│────────────────│
│ ○ add-metrics      │ ● api-refactor      │ ? docs-writer      │ ✓ lint-pass    │
│   sonnet           │   opus · 12m · 71%  │   «Можна видалити  │ ✓ bump-deps    │
│ ○ i18n-ua          │ ◐ test-fixer        │    old/README?»    │ ✓ typo-fix     │
│   haiku            │   sonnet · 4m       │ ! deploy-check     │ ✓ ci-cache     │
│ ○ perf-audit       │ ● migrations        │   exit 1 · retry?  │ ✓ readme       │
│   opus             │   haiku · 1m        │                    │                │
├────────────────────┴─────────────────────┴────────────────────┴────────────────┤
│ opus 62% ↻1h12m   sonnet 94% ⚠ ↻8m   haiku 14%            h/l column  j/k card │
└────────────────────────────────────────────────────────────────────────────────┘
```

`enter` на картці → той самий детальний екран, що у варіанті A.

**+** одразу видно «вузьке місце» і все, що чекає на тебе.
**−** менше деталей на картці; погано, якщо агентів >30.

## Варіант D — мінімальний (status line / tmux)

Не окремий застосунок, а один рядок для tmux / Claude Code statusline + `agents-farm watch` для детального.

```
 ●3 ?1 !1 │ opus 62% │ sonnet 94%⚠ 8m │ haiku 14%
```

Корисно як доповнення до A/B/C, а не замість.

## Кращі практики UX у терміналі (що закладаємо)

1. **Колір + символ + текст.** Ніколи не кодувати стан лише кольором (дальтонізм, моно-термінали). Поважати `NO_COLOR`.
2. **Найважливіше — вгорі.** «Чекає на тебе» і помилки сортуються першими, дублюються в заголовку (`1 waiting`).
3. **Клавіші vim + стрілки**, `?` — завжди показує довідку, футер з 5–7 ключовими шорткатами під поточний контекст.
4. **Прогресивне розкриття.** Список → деталі → zoom. `enter` глибше, `esc` назад, `space` згорнути/розгорнути, `E` все.
5. **Адаптивність.** <80 кол: одна панель (список ↔ деталі). 80–120: дві. >120: дві + feed. Обробка `SIGWINCH`.
6. **Не блимати.** Diff-рендер, оновлення ≤10 fps, спінер лише на активних рядках. Курсор/виділення не стрибає при пересортуванні (тримаємо за id агента).
7. **Пошук і фільтр `/`** — fuzzy, підсвітка збігів, фільтри `status:waiting model:opus`.
8. **Дії з підтвердженням** для руйнівних (`x kill` → `Kill api-refactor? y/N`), undo де можна (pause/resume).
9. **Копіювання та вихід назовні:** `y` — копіювати (OSC 52, працює через ssh), `o` — відкрити файл/лог у `$EDITOR`, `a` — attach до сесії агента.
10. **Сповіщення:** дзвіночок `\a` / нативне повідомлення ОС, коли агент переходить у `waiting` або ліміт >90%. Вимикається в конфігу.
11. **Unicode з fallback** на ASCII (`[#####-----]`) для старих терміналів.
12. **Неінтерактивний режим:** `agents-farm status --json` — для скриптів і statusline.

## Стек (коротко)

| Варіант | Плюси | Мінуси |
|---|---|---|
| **Go + Bubble Tea + Lip Gloss** ⭐ | один бінарник, швидко, гарні компоненти (list, viewport, table) | більше коду на layout |
| Python + Textual | найшвидше прототипувати, CSS-подібні стилі, вбудовані віджети (Tree, DataTable, Collapsible) | потрібен Python-рантайм |
| Rust + ratatui | максимальна швидкість | найповільніша розробка |
| TS + Ink | React-модель, легко якщо команда на JS | слабше з великими списками |

Рекомендація: **варіант A як основний + перемикач `b` на Kanban (B)** і `--statusline` (D). Прототип — на Textual (день-два), продакшн — Bubble Tea, якщо потрібен один бінарник.

## Відкрите питання — джерело даних

Звідки брати стан агентів — від цього залежить архітектура:
- **Claude Code сесії** (локальні транскрипти `~/.claude/projects/*` + hooks, що пишуть події у файл/сокет);
- **власний оркестратор** (агенти пишуть події в SQLite / Redis / HTTP);
- **API провайдера** для лімітів (rate-limit заголовки відповідей, usage endpoint).
